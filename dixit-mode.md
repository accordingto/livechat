# Dixit / 妙語說書人

The last game on the Hub list. Uses existing Hub room/player links and the current standard Dixit base-game rules (3–8 players), with 84 independently generated original picture cards. This is an unofficial adaptation. No original commercial card art, logo, or branded board is included.

## Rules

Deal six cards per player (seven for three players). The Storyteller secretly picks one card and announces a clue. Everyone else submits one matching card (two each for three players). Shuffle all submitted cards once and number them publicly. Each non-Storyteller secretly votes for one card; nobody can vote for an own decoy. Votes lock after submission. Only after every vote may the host reveal all owners/votes and score.

- Some guesses correct: Storyteller +3 and each correct guess +3.
- Everyone or nobody correct: Storyteller 0; everyone else +2.
- Every non-Storyteller gets an extra +1 per vote on their cards in all branches, without an Odyssey bonus cap.

Discard played cards, refill hands, rotate the Storyteller to the next player in roster order. When the draw pile cannot replenish everyone, mix its remaining cards with discards before refilling. By default, finish after a round with any score at least 30. The host can choose an integer target from 5–100 before dealing; this is an optional house rule. Highest score wins; ties share the win. Other scoring follows the current base-game edition, not older deck-exhaustion endings or Odyssey double voting.

## Host and player operation

When changing from another Hub game, open this host page and click Open this table. The existing player links switch to the Dixit lobby, even if their previous game has no End control. A restored table whose players have moved away shows these opening controls again; its old gameplay controls remain inactive until the host explicitly opens a new table.

Set up 3–8 players in the Hub. Open Dixit, designate which player is HOST, then click Open this table. Use Open my host player card to open that player's existing private link. All gameplay and host operations work from that one private card: select the first Storyteller, deal, play/vote with your own hand, pause/resume, reveal, start the next round, cancel, and replay. Other players cannot issue host operations. Replays preserve the designated host; older saved games without a host seat use player 1.

When the designated host card is open in the same browser that owns the saved Hub room, it automatically runs the trusted-host executor, including while hidden whenever the browser permits execution. The shared table can be hidden or closed. This requires the existing local room credentials; no control credential is added to player links or public projections. If the host card uses another device or browser without those saved credentials, the original shared table must remain open as the executor. At least one authorized host page must remain running and connected; if the browser suspends all host pages or the device sleeps, processing resumes when a host page wakes. Game actions do not execute on a server.

The Storyteller selects a card, says the clue aloud on the call, then confirms submission. There is no clue text field or recording requirement. The prominent phase bar carries the current action instructions; the private-hand identity line and duplicate spoken-clue banner are omitted. Legacy rounds with a typed clue still display it. Three-player submissions require two distinct cards. The public screen has no private hand and does not vote. Cancel and replay confirmations appear within the host card rather than a browser popup.

The sticky information bar makes the current phase the primary heading, accompanied by the player's next action and live submission/vote progress. The extra Dixit/round/Storyteller subtitle is removed. During voting, every participant has a public status in that information bar: voted, waiting to vote, Storyteller (no ballot required), or sitting out after shared recovery. An offline player who already voted still shows voted; no ballot choice or card ownership is exposed. The status list is removed after voting ends. Players and scores sit below the cards, expanded by default; manually closing or opening them survives synchronized repaints. Once all votes arrive, the host starts a shared 3–2–1 countdown. The Storyteller's card appears in the center after 3 seconds; all other pictures with at least one vote appear to its right 1.2 seconds later. Individual card votes determine descending order, with equal counts retaining shuffled table order. The answer stays once in the center with its own vote count. The first right image has its owner and vote count in the shared header row; later large pictures carry their own owner/count metadata above the image and extend downward. Zero-vote pictures remain in the complete round gallery. Vote counts and owners appear only after the full result is public. The left column shows each player's round gain and only their positive scoring sources, with the viewing player first. Zero gains show only the player's name and 0; cumulative totals and voter names are omitted from this panel. Each vote-bonus line gives the number of votes on that player's cards. The first score row and both picture tops share one content row, with titles and owner metadata above it. These points remain visible until the host starts another round, including after refresh. There is no score popup, overlay, dismiss control or timer. A collapsed result breakdown remains below the cards. The right gallery and complete round gallery identify owners above their images; the central answer uses its Storyteller heading. Phones stack large pictures vertically, followed by round points. Shared deadlines persist through refresh; pausing freezes the reveal and resuming shifts its deadlines. Previously completed rounds appear directly with their points, without replaying the countdown.

Pictures dominate the page: hands use three large columns on desktop, two on medium screens, and one full-width column on phones below 600px. The reveal keeps points on the left, the answer in the center and all other voted cards on the right above 600px; its score column is narrower than each picture column. The scoreboard and instructions are compact. Select cards by tapping the picture, then confirm separately. Enlargement buttons and the full-screen focus gallery have been removed; the existing large cards preserve the complete 3:4 composition.

The browser transport follows the Hub's established trusted-host Firebase design. Canonical game state persists at a random host control token, with a 90-second host lease and atomic per-path transactions. Hiding a host page updates its visibility but does not release its lease or stop receiving commands. A visible authorized host page can immediately take over a hidden executor; hidden pages cannot steal an active visible owner's lease. The foreground private host card retains priority over the shared screen. Refresh uses a per-tab resume identity to replace the previous private executor without waiting for lease expiry. A separate saved browser identity lets a newly opened trusted HOST tab replace a closed tab's lingering lease immediately, even when unloading aborted its asynchronous release. The identity is bound to the canonical lease owner, never exposed in player links or projections, and does not grant credentials. Older tabs cannot fight a visible replacement but can resume after it hides, closes or expires; different browser identities cannot steal a visible private lease. Legacy private leases receive one identity migration on takeover. Reconnection renews the lease, and delayed lease transactions refresh an expired captured deadline immediately. Private cards can still select pictures and submit an atomic request during a stale host heartbeat; actual network disconnection and pending requests remain protected. An expired host heartbeat displays a reconnection message instead of falsely treating a background card as an offline host. State-changing requests execute only when a connected authorized host executor runs.

Outgoing projections use independent, latest-only queues for each player. A delayed write to one card cannot block all other players, and obsolete queued heartbeat updates are replaced rather than accumulated. The initial player snapshots for a new session persist under the secret control node, so a replacement executor can safely finish an interrupted opening without overwriting cards switched to another game. Existing mailboxes and pending requests survive projection updates.

This is not a server-executed or malicious-host-proof game. The trusted host browser necessarily receives canonical state. The shared host UI receives view 0; each player projection receives only their own hand, submissions, and vote. During REVEALING, only the countdown deadlines are public initially; after the first deadline only the answer card is added. Owners, popularity, other ballots, and updated points remain hidden until the second deadline. The host lease owner advances these stages automatically. Listener identity determines request actor, and canonical hostPlayerNum determines host permission; supplied actor/hostControls flags cannot promote another player. Session/phase/action receipts and atomic mailboxes guard stale/duplicate requests. Restart requests from the host player's mailbox replace the session and clear old requests safely. Switching games suspends the old host instead of overwriting the newer player's card.
